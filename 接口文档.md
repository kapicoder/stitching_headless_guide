# stitching_headless API 接口文档

## 1. 启动服务

Compose 启动：

```bash
cd /home/stitching/stitching_headless
HOST_PORT=8002 docker compose up -d
```

查看api详细信息：

```bash
docker compose logs -f stitching-headless-api \
  | grep --line-buffered -v 'GET /health'
```

关闭api：

```bash
docker compose down
```

## 2. 健康检查

`GET /health`

返回示例：

```json
{
  "status": "ok",
  "module": "stitching_headless"
}
```

## 3. 拼接接口

`POST /headless_stitching_image`

兼容路由：`POST /visible_stitching_image`、`POST /stitch`

请求体示例：

```json
{
  "input_folder": "./data",
  "output_path": "./output/headless_example_result.jpg",
  "overwrite": true,
  "limit": 6,
  "show_progress": true,
  "settings": {
    "algorithm": "stitcher"
  }
}
```

也可以传 `image_paths` 数组替代 `input_folder`。

### 人工四点引导拼接（`guided_affine`）

每张图提交在同一画布上的四个角点，顺序为左上、右上、右下、左下。坐标单位为原始图像像素，X 向右、Y 向下；第一张图固定为参考，例如宽 2000、高 1500 时四点必须是 `(0,0)`、`(2000,0)`、`(2000,1500)`、`(0,1500)`。其他图允许负坐标。前端使用缩略图摆放时，须先将坐标换算到原图尺度。

```json
{
  "images": [
    {
      "path": "./data/01.tif",
      "corners": [
        [0, 0],
        [2000, 0],
        [2000, 1500],
        [0, 1500]
      ]
    },
    {
      "path": "./data/02.tif",
      "corners": [
        [1700, 20],
        [3700, 20],
        [3700, 1520],
        [1700, 1520]
      ]
    }
  ],
  "output_path": "./output/guided_result.tif",
  "settings": { "algorithm": "guided_affine", "georef_mode": "none" }
}
```

### 指定匹配区域框（`matching_regions`）

在 `guided_affine` 模式下，可通过请求体顶层的 `matching_regions` 指定特征匹配区域。
该字段与 `images`、`settings` 同级，不放在 `settings` 内。主接口及兼容路由均支持。

以下示例假定两张输入图均为 `4000×24000`，第二张向右放置 3000 像素，
选择重叠带的上、下两部分参与配准。路径须替换为 API 进程实际可访问的路径。

```json
{
  "images": [
    {
      "path": "./test_data/test_data_4000x24000/stitch_test_01.jpg",
      "corners": [
        [0, 0],
        [4000, 0],
        [4000, 24000],
        [0, 24000]
      ]
    },
    {
      "path": "./test_data/test_data_4000x24000/stitch_test_02.jpg",
      "corners": [
        [3000, 0],
        [7000, 0],
        [7000, 24000],
        [3000, 24000]
      ]
    }
  ],
  "matching_regions": [
    { "id": "top", "rect": [3000, 0, 1000, 10000] },
    { "id": "bottom", "rect": [3000, 12000, 1000, 12000] }
  ],
  "output_path": "./output/regions_result.jpg",
  "settings": {
    "algorithm": "guided_affine",
    "georef_mode": "none",
    "nfeatures": 4000,
    "medium_megapix": 2
  }
}
```

区域框字段定义：

| 字段               | 类型          | 约束与含义                                                                                              |
| ------------------ | ------------- | ------------------------------------------------------------------------------------------------------- |
| `matching_regions` | array[object] | 可选，最多 32 个框；省略或传空数组表示不使用框选限制。非空数组仅支持 `guided_affine`。                  |
| `id`               | string        | 框的唯一非空标识，用于返回区域诊断信息。                                                                |
| `rect`             | array[number] | `[x, y, width, height]`，前两项为左上角，后两项为宽高；所有值须为有限数值，不接受布尔值，宽高须大于零。 |

**坐标系：** 框使用 `images[].corners` 所在的初始共享画布坐标，以原图像素尺度表示，
X 向右、Y 向下。不是浏览器屏幕坐标，也不是最终输出图坐标。
第一张图左上角为 `(0,0)`；框允许负坐标及部分越界，算法按实际搜索区域和有效像素裁剪。
框参数非法或非空框数组用于其他算法时，接口返回 HTTP 400。

**匹配规则：**

- 不需要为框传入图片 ID；算法根据框与候选图像对两侧搜索区域的交集自动关联。
- 有关联框的图像对仅使用框内特征，同一个框内的两侧互相匹配，不跨框匹配；无关联框的图像对继续自动匹配。
- 重叠框按数组顺序分配有效像素，后面的框不再使用前面框已占用的像素。
- 框只限制配准使用的特征区域，最终仍投影、融合完整图像。
- 框选匹配失败时保留人工初始位置，不扩大到框外寻找特征。所有框的对应点用于同一个图像对变换估计，并非每框独立拼接。

### 请求参数说明

| 参数名             | 类型          | 是否必填                 | 默认值 | 可选值/约束                                              | 作用                                                                                                                                               |
| ------------------ | ------------- | ------------------------ | ------ | -------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| `input_folder`     | string        | 与 `image_paths` 二选一  | 无     | 本地或容器内可访问的目录路径                             | 输入图片目录，API 会读取其中的 `jpg/jpeg/png/tif/tiff` 文件并按文件名排序。                                                                        |
| `image_paths`      | array[string] | 与 `input_folder` 二选一 | 无     | 至少 2 张图片路径                                        | 直接指定待拼接图片列表，顺序即拼接输入顺序；传入该字段时不会扫描目录。                                                                             |
| `images`           | array[object] | `guided_affine` 必填     | 无     | 至少 2 张，不能与 `image_paths`、`input_folder` 同时使用 | 每项包含 `path` 和共享画布中的 `corners`，见人工四点引导示例；不支持 `limit`。                                                                     |
| `matching_regions` | array[object] | 否                       | `[]`   | 最多 32 个框，非空时仅支持 `guided_affine`               | 指定配准特征区域，每项包含唯一 `id` 和 `rect: [x,y,width,height]`，详见上节。                                                                      |
| `output_path`      | string        | 是                       | 无     | 非空路径                                                 | 拼接结果保存路径；相对路径按 API 进程工作目录解析。后缀为 `.tif` 或 `.tiff` 时写出 COG，并复制左上输入 TIFF 的 CRS/GeoTransform 作为粗略地理参考。 |
| `overwrite`        | boolean       | 否                       | `true` | `true`、`false`                                          | 输出文件已存在时是否覆盖；为 `false` 且文件存在时接口返回错误。                                                                                    |
| `limit`            | integer/null  | 否                       | `null` | 大于 0 的整数，或不传                                    | 只使用排序后的前 N 张图片；调试时可减小该值，正式处理可不传。                                                                                      |
| `show_progress`    | boolean       | 否                       | `true` | `true`、`false`                                          | 是否在服务日志中输出 Stitcher 的 20 个阶段进度和逐图融合进度。                                                                                     |
| `settings`         | object        | 否                       | 见下表 | JSON object                                              | 拼接算法参数集合；也可以把其中字段直接放在请求体顶层，效果相同。                                                                                   |

### `settings` 参数说明

| 参数名                  | 类型    | 默认值         | 可选值/约束                                                             | 作用                                                                                                                                                                                                                      |
| ----------------------- | ------- | -------------- | ----------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `algorithm`             | string  | `stitcher`     | `stitcher`、`origin`、`local_refine`、`apap`、`guided_affine`           | 选择拼接算法。`guided_affine` 使用人工像素坐标作为初始位置，其他模式使用视觉特征定位；TIFF 由 GDAL 解码，经纬度和投影信息不参与图像定位。                                                                                 |
| `detector`              | string  | `sift`         | `orb`、`sift`、`brisk`、`akaze`                                         | 特征点检测算法。`sift` 稳定性通常较好但较慢；`orb` 较快；`akaze` 和 `brisk` 可作为速度与稳定性的折中尝试。                                                                                                                |
| `nfeatures`             | integer | `8000`         | 大于 0                                                                  | 每张图最多提取的特征点数量。值越大，弱纹理或大图匹配机会越高，但耗时和内存也会上升。                                                                                                                                      |
| `match_conf`            | number  | `0.2`          | 大于 0 且小于等于 1                                                     | 特征描述子匹配筛选阈值，供 `stitcher` 和 `origin` 使用。值越大筛选越严格；对 SIFT 使用过高的值可能让匹配置信度被 OpenCV 归零并导致图片被剔除。                                                                            |
| `matcher_type`          | string  | `homography`   | `homography`、`affine`                                                  | 特征匹配几何模型。普通透视全景常用 `homography`；航拍瓦片、地图切片、近似正射图像更适合 `affine`。                                                                                                                        |
| `range_width`           | integer | `1`            | `-1` 或大于等于 1                                                       | 特征匹配范围。`1` 只匹配输入顺序中相邻的图片，适合顺序可靠的连续航拍图；`-1` 比较所有图片组合，适合输入顺序不确定的情况，但图片较多时耗时明显增加。                                                                       |
| `estimator`             | string  | `homography`   | `homography`、`affine`                                                  | 相机参数估计模型，建议与 `matcher_type` 保持一致。                                                                                                                                                                        |
| `adjuster`              | string  | `ray`          | `ray`、`reproj`、`affine`、`no`                                         | 相机参数优化方式。`ray` 常用于普通全景；`reproj` 优化重投影误差；`affine` 适合仿射模型；`no` 表示不做 bundle adjustment。                                                                                                 |
| `warper_type`           | string  | `spherical`    | 见下方 `warper_type` 表                                                 | 图像投影方式，决定每张图在融合前如何变换到统一画布。                                                                                                                                                                      |
| `wave_correct_kind`     | string  | `horiz`        | `horiz`、`vert`、`auto`、`no`                                           | 波形校正方式。`horiz` 适合水平全景；`vert` 适合竖向拼接；`auto` 自动选择；航拍/正射瓦片通常可用 `no`。                                                                                                                    |
| `compensator`           | string  | `gain_blocks`  | `gain_blocks`、`gain`、`channel`、`channel_blocks`、`no`                | 曝光补偿方式。`gain_blocks` 按块修正亮度差；`gain` 做整体增益补偿；`channel`/`channel_blocks` 分通道补偿；`no` 不补偿。                                                                                                   |
| `finder`                | string  | `dp_colorgrad` | `dp_color`、`dp_colorgrad`、`gc_color`、`gc_colorgrad`、`voronoi`、`no` | 接缝查找方法，供 `stitcher` 和 `origin` 使用。用于决定重叠区域中从哪条路径切换图片；具体取舍见下方 `finder` 表。                                                                                                          |
| `blender_type`          | string  | `feather`      | `feather`、`multiband`、`no`                                            | 图像融合方法，供 `stitcher` 和 `origin` 使用。决定接缝 mask 确定后如何平滑重叠区域；具体取舍见下方 `blender_type` 表。                                                                                                    |
| `blend_strength`        | number  | `1`            | 大于等于 0                                                              | 融合范围/强度，供 `stitcher` 和 `origin` 使用。值越大，过渡区域通常越宽，同时可能增加计算量和内存占用。                                                                                                                   |
| `confidence_threshold`  | number  | `0.3`          | 大于等于 0                                                              | 图片匹配置信度阈值。值越高越严格，过高可能剔除可拼接图片；值越低越宽松，错误匹配风险更高。                                                                                                                                |
| `medium_megapix`        | number  | `1.0`          | 大于 0                                                                  | 特征检测阶段的图像分辨率，单位 Mpx。值越大越可能匹配成功，但速度更慢、内存更高。                                                                                                                                          |
| `low_megapix`           | number  | `0.3`          | 大于 0                                                                  | 接缝查找、曝光估计等低分辨率阶段的图像分辨率，单位 Mpx。                                                                                                                                                                  |
| `final_megapix`         | number  | `10`           | 不能为 0；`-1` 表示原图分辨率                                           | 最终输出分辨率，单位 Mpx。设为较小正数可加快测试并降低内存，设为 `-1` 尽量保留原始分辨率。                                                                                                                                |
| `optimized_tiff_io`     | boolean | `true`         | `true`、`false`                                                         | 是否启用 GDAL 目标尺寸解码、overview 和 medium 单次打开优化；关闭后使用完整读取再缩放的旧流程。                                                                                                                           |
| `parallel_image_io`     | boolean | `true`         | `true`、`false`                                                         | 是否并行读取和缩放输入图像。                                                                                                                                                                                              |
| `image_io_workers`      | integer | `2`            | 大于等于 1                                                              | 并行图像读取线程数；仅在 `parallel_image_io=true` 时发挥作用。                                                                                                                                                            |
| `prefetch_final_images` | boolean | `true`         | `true`、`false`                                                         | Final 阶段是否在处理当前图像时预取后续图像。                                                                                                                                                                              |
| `cache_all_valid_masks` | boolean | `true`         | `true`、`false`                                                         | 是否在单次请求内缓存全有效 mask，避免 low/final 重复读取。                                                                                                                                                                |
| `shared_warp_maps`      | boolean | `true`         | `true`、`false`                                                         | 最终阶段是否让图像与 mask 共用投影映射。                                                                                                                                                                                  |
| `georef_mode`           | string  | `affine_fit`   | `affine_fit`、`copy`、`none`                                            | COG 地理参考策略。`affine_fit` 在全 affine 拼接时复用已有投影关系，以每张图最多 9 个固定点拟合 GeoTransform，RMSE 超过 25 像素或条件不足时自动退回 `copy`；`copy` 使用左上输入 TIFF 的近似地理参考；`none` 不写地理参考。 |
| `crop`                  | boolean | `true`         | `true`、`false`                                                         | 是否裁剪拼接结果周围的黑边。                                                                                                                                                                                              |
| `apap_grid_parts`       | integer | `2`            | 大于 0                                                                  | 仅 `algorithm=apap` 时使用的兼容高级参数。                                                                                                                                                                                |
| `apap_sigma`            | number  | `0.15`         | 大于 0                                                                  | 仅 `algorithm=apap` 时使用的兼容高级参数；`0 < apap_sigma <= 1` 表示当前图像高度比例。                                                                                                                                    |
| `apap_min_matches`      | integer | `12`           | 大于等于 4                                                              | 仅 `algorithm=apap` 时使用的兼容高级参数。                                                                                                                                                                                |
| `apap_blend_width`      | integer | `80`           | 大于等于 0                                                              | 仅 `algorithm=apap` 时使用的兼容高级参数。                                                                                                                                                                                |

`local_refine` 主要用于改善“全局能拼接、但局部区域错位”的情况，例如大图上半部分对齐较好、下半部分残差更大的正射或遥感瓦片。该模式不要求调用方额外传局部参数；局部带数、平滑强度和羽化宽度由服务内部固定默认值控制。

### `finder` 可选值

`finder` 控制 `stitcher` 或 `origin` 算法如何在图像重叠区域中选择接缝。接缝查找负责“在哪里切换图片”，后续的 feather 或 multiband 融合负责“如何平滑切换区域”；关闭接缝查找不会关闭融合。

| 参数值         | 方法                      | 速度 | 特点与适用场景                                                                                              |
| -------------- | ------------------------- | ---- | ----------------------------------------------------------------------------------------------------------- |
| `dp_colorgrad` | 动态规划，颜色与梯度代价  | 较快 | 默认值。兼顾速度和接缝质量，适合普通航拍、正射瓦片和大多数生产场景。                                        |
| `dp_color`     | 动态规划，仅颜色代价      | 快   | 不计算梯度，适合对齐准确、结构边缘不复杂的规则重叠图像。                                                    |
| `gc_colorgrad` | Graph Cut，颜色与梯度代价 | 最慢 | 接缝选择通常更精细，适合视差、建筑边缘或移动物体明显的原始航拍照片，但大图耗时较高。                        |
| `gc_color`     | Graph Cut，仅颜色代价     | 较慢 | 比 `gc_colorgrad` 简单，适合需要 Graph Cut 但希望减少部分计算量的场景。                                     |
| `voronoi`      | Voronoi 区域分割          | 很快 | 按几何区域划分接缝，不主动寻找最低差异路径；适合已准确配准的正射图、地图瓦片和性能测试。                    |
| `no`           | 不执行接缝搜索            | 最快 | 保留原始有效 mask，并由融合器处理重叠区。适合同源影像裁片或完全对齐的数据；真实航拍可能出现重影或明显过渡。 |

推荐配置：

- 普通航拍或正射瓦片：`dp_colorgrad`。
- 对齐准确且更关注速度：`dp_color` 或 `voronoi`。
- 同一幅正射图裁出的重叠测试片：`no` 或 `voronoi`。
- 原始飞机/无人机连续照片且局部视差明显：`gc_colorgrad`。

示例：

```json
{
  "settings": {
    "algorithm": "stitcher",
    "finder": "dp_colorgrad",
    "low_megapix": 0.3
  }
}
```

`finder` 在 `low_megapix` 指定的低分辨率图像上运行。提高 `low_megapix` 可能改善复杂接缝的细节，但会增加耗时和内存；对于大尺寸航拍图，建议从 `0.3` 开始测试。

### `blender_type` 可选值

`blender_type` 控制 `stitcher` 或 `origin` 算法在最终输出分辨率下如何融合各张图片。`finder` 负责选择接缝路径，`blender_type` 负责平滑接缝周围的颜色和亮度过渡；融合可以弱化接缝，但不能修复错误匹配或明显的几何错位。`origin` 使用第三方库的原生融合器；`stitcher` 在 `feather` 模式下使用项目自定义高斯羽化实现。

| 参数值      | 方法         | 速度与内存         | 特点与适用场景                                                                                                                 |
| ----------- | ------------ | ------------------ | ------------------------------------------------------------------------------------------------------------------------------ |
| `feather`   | 羽化融合     | 较快、内存相对较低 | 默认值。根据权重在接缝附近做平滑过渡，适合已准确配准的航拍、正射瓦片、地图切片和大尺寸图像。曝光差异较大时可能出现宽渐变带。   |
| `multiband` | 多频段融合   | 最慢、内存最高     | 在多个频率层级分别融合，能较好处理曝光、颜色和低频亮度差异，适合普通相机全景或接缝较复杂的数据。大画布可能显著增加耗时和内存。 |
| `no`        | 不做平滑融合 | 最快、内存最低     | 直接按照 mask 合成图像，不对边界做平滑处理。适合调试、性能测试或内容完全一致的同源裁片；真实航拍通常会出现硬边界。             |

推荐配置：

- 大尺寸航拍、正射影像或内存受限环境：`feather`。
- 图片存在明显曝光或颜色差异，且内存充足：`multiband`。
- 只验证匹配、投影位置或运行性能：`no`。

示例：

```json
{
  "settings": {
    "algorithm": "stitcher",
    "finder": "dp_colorgrad",
    "blender_type": "feather",
    "blend_strength": 1
  }
}
```

`blend_strength` 的含义会随融合器变化：对 `feather` 主要影响羽化过渡宽度，对 `multiband` 会间接影响金字塔频段数量。较大的值不一定产生更好的结果；对于超大航拍图，建议从 `1` 开始，确认接缝过渡不足后再逐步增大。

### `warper_type` 可选值

`warper_type` 控制每张输入图像在融合前采用哪一种几何投影方式。当前环境支持以下取值：

| 参数值                          | 特点                                                   | 适合场景                                   |
| ------------------------------- | ------------------------------------------------------ | ------------------------------------------ |
| `plane`                         | 平面投影，形变少，但视角跨度大时边缘容易拉伸或对不齐。 | 扫描图、局部平面、重叠区域不大的普通图片。 |
| `affine`                        | 仿射投影，适合平移、缩放、旋转为主的图像。             | 航拍瓦片、遥感图、地图切片、近似正射图像。 |
| `cylindrical`                   | 圆柱投影，水平展开较自然，垂直方向变形较小。           | 水平全景、相机水平旋转拍摄。               |
| `spherical`                     | 球面投影，能处理更大的视角变化。                       | 普通全景拼接、视角跨度较大的非正射拍摄。   |
| `fisheye`                       | 鱼眼投影，保留鱼眼视角特征。                           | 鱼眼镜头或超广角图像。                     |
| `stereographic`                 | 立体投影，局部形状保持较好，但边缘可能夸张。           | 艺术化全景、广角场景。                     |
| `mercator`                      | 墨卡托投影，水平全景展开稳定，但上下边缘拉伸明显。     | 360 水平全景、地图式展开。                 |
| `transverseMercator`            | 横轴墨卡托，适合纵向展开。                             | 纵向全景、竖向扫描式拼接。                 |
| `compressedPlaneA2B1`           | 压缩平面投影，减轻平面投影边缘拉伸。                   | 平面投影边缘变形过大时尝试。               |
| `compressedPlaneA1.5B1`         | 比 `compressedPlaneA2B1` 压缩稍弱。                    | 平面投影的形变和视野折中。                 |
| `compressedPlanePortraitA2B1`   | 竖版压缩平面投影。                                     | 竖向画幅或竖向全景。                       |
| `compressedPlanePortraitA1.5B1` | 竖版压缩平面投影，压缩稍弱。                           | 竖向画幅折中方案。                         |
| `paniniA2B1`                    | Panini 投影，兼顾广角和直线观感。                      | 建筑、街景、广角全景。                     |
| `paniniA1.5B1`                  | Panini 投影，压缩稍弱。                                | 建筑、街景的形变折中。                     |
| `paniniPortraitA2B1`            | 竖版 Panini 投影。                                     | 竖向广角、建筑图。                         |
| `paniniPortraitA1.5B1`          | 竖版 Panini 投影，压缩稍弱。                           | 竖向广角折中方案。                         |

对于 `stitching_headless/data` 这种航拍或遥感瓦片，优先建议使用 `affine`，并配套使用仿射匹配和估计参数：

```json
{
  "matcher_type": "affine",
  "estimator": "affine",
  "adjuster": "affine",
  "wave_correct_kind": "no",
  "warper_type": "affine"
}
```

示例中的 `spherical` 更偏向普通相机旋转拍摄的全景图。如果输入主要是正射瓦片、地图切片或航拍拼接，`affine` 通常更贴近数据几何关系；如果 `affine` 拼接不稳定，可以再尝试 `plane` 或回退到 `spherical`。

返回示例：

```json
{
  "status": "done",
  "output_path": "output/headless_example_result.jpg",
  "progress_path": "output/progress.txt",
  "image_count": 6,
  "valid_paths": ["data/xxx.tif"],
  "output_width": 1200,
  "output_height": 800,
  "algorithm": "local_refine",
  "cog": false,
  "settings": {}
}
```

### TIFF/COG 输入输出

输入 `.tif/.tiff` 时，GDAL 仅负责读取多波段、位深和 NoData/Alpha mask，并转换为 OpenCV 使用的 `uint8 BGR`。后续位置估计、变形、接缝和融合全部由所选视觉算法完成，不读取经纬度来决定图像位置。

当 `output_path` 使用 `.tif` 或 `.tiff` 后缀时，输出会使用 COG 驱动写出。当前策略包括：

1. 使用 `COG` 驱动生成带瓦片布局、DEFLATE 压缩、自动 overviews 的 GeoTIFF。
2. 默认 `georef_mode=affine_fit`：当匹配、估计、优化和 warper 使用 affine 流程时，复用最终投影关系生成少量控制点并稳健拟合六参数 GeoTransform，不重新执行特征检测或整图重采样。
3. affine 拟合条件不足、CRS 不一致、矩阵退化或 RMSE 超过 25 像素时，自动退回复制地理位置最左上输入 TIFF 的 CRS/GeoTransform；无法比较时使用输入列表中第一张具有有效地理参考的 TIFF。
4. 输出元数据包含 `GEOREFERENCE_METHOD`、控制点数量和拟合 RMSE；所有自动结果均标记 `GEOREFERENCE_QUALITY=APPROXIMATE`，不得用于精确测量。
5. 返回体中的 `cog` 字段会标记本次输出是否按 TIF/COG 路径保存。

示例：

```json
{
  "input_folder": "./data",
  "output_path": "./output/headless_example_result.tif",
  "overwrite": true,
  "limit": 6,
  "show_progress": true,
  "settings": {
    "algorithm": "local_refine"
  }
}
```
